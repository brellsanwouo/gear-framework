# P4 / T4 — Measured task: iterative schedule refinement

## Objective

Produce a final conference programme through exactly two review-and-refinement iterations. This task is measured and receives no user input at runtime.

## Situation

The conference retains the P3 hours, rooms, presentations, durations, audiences, equipment requirements, and availability constraints. The conference-wide break remains 10:20–10:40. The following additional facts apply:

- `Reliable AI Systems` is the opening presentation and starts at 09:00 in `Auditorium`.
- Bruno Lee is available from 09:40 onward.
- `Human-Centred Evaluation` starts immediately after the break at 10:40.
- Two consecutive presentations in the same room require a 5-minute transition, except when the conference-wide break separates them.

For completeness: `Auditorium` has capacity 120, a projector, and video conferencing; `SeminarRoom` has capacity 50 and a projector but no video conferencing. The presentations are Reliable AI Systems / Alice Martin / 40 min / audience 90 / projector; Efficient Scientific Workflows / Bruno Lee / 40 min / audience 45 / projector; Reproducible Experiments / Carla Diaz / 45 min / audience 80 / video conferencing / available 10:40–12:00; Open Research Data / David Kim / 30 min / audience 70 / projector / must finish by 10:20; Human-Centred Evaluation / Elena Rossi / 50 min / audience 45 / projector / available 09:40–12:00; and Research Software Careers / Farid Noor / 35 min / audience 35 / no equipment requirement.

## Agents

![P4 architecture](/data/ConferenceScheduling/images/P4.svg)

### `ConferenceContextAgent`

- Purpose: `present the conference situation and its factual information.`
- TaskDescription: State only all conference facts, including hours, break, rooms, presentation attributes, availability, fixed starts, and transition time. Do not formulate a problem, analyze constraints, propose a schedule, or explain later agents.
- ExpectedOutput: A complete factual conference brief, with no analysis or schedule.

### `SchedulePlannerAgent`

- Purpose: `build an initial conference schedule.`
- TaskDescription: Produce a complete initial schedule from the factual context. Include every presentation exactly once and attempt to satisfy every stated constraint.
- ExpectedOutput: An initial schedule table with `Start`, `End`, `Room`, `Presentation`, and `Speaker` columns.

### `ScheduleReviewerAgent`

- Purpose: `identify problems in the current schedule.`
- TaskDescription: Compare the current schedule with every factual constraint. Identify each violation precisely, naming the affected presentation, time, room, and rule. If none exist, return `NO VIOLATIONS` and identify any harmless formatting or stability improvement separately.
- ExpectedOutput: A concise, actionable review report that does not rewrite the schedule.

### `ScheduleRefinerAgent`

- Purpose: `improve the current schedule.`
- TaskDescription: Correct the current schedule using the review report while preserving as many already valid assignments as possible. Return a complete schedule, not a patch.
- ExpectedOutput: A complete refined schedule table ready to become the next iteration's current schedule.

### `FinalScheduleAgent`

- Purpose: `produce the final conference schedule.`
- TaskDescription: Return only the final refined programme. Do not include analysis, review notes, explanations, or alternative schedules.
- ExpectedOutput: Only a Markdown table with `Start`, `End`, `Room`, `Presentation`, and `Speaker` columns, sorted by start time and then room.

## Orchestration

- Mode: sequential with a fixed iterative module
- Order: `ConferenceContextAgent -> SchedulePlannerAgent -> [ScheduleReviewerAgent -> ScheduleRefinerAgent] x2 -> FinalScheduleAgent`
- Iteration 1: the reviewer receives the context and initial schedule; the refiner receives that schedule and review.
- Iteration 2: the first refined schedule becomes the current schedule; the same reviewer-refiner sequence runs once more.
- Exact count: execute the reviewer-refiner module exactly two times—never one and never three.
- Finalization: `FinalScheduleAgent` receives the second refined schedule.
- Runtime input: none
